# Sound Lab (ideal signals, modeled strikes and held instruments, moving pitch, beats, harmonics and noise)

Standalone browser-based Sol tool. Open [index.html](index.html) from the site or serve the repository as a static website. No build, external dependencies, microphone permission, uploads or server are required. Local WAV recording uses the browser's AudioWorklet API and requires a supported browser on a secure origin (as provided by the deployed site).

## Shipped in P1

- Sine, triangle, square and sawtooth using Web Audio's built-in oscillators.
- Explicit click/tap to start audio; large Play/Stop toggle and always-visible master Stop. At the default 40% volume, the waveform gain is 0.12 (40% of a 0.30 cap); short ramps avoid abrupt starts, stops or shape changes. No simultaneous instrument tracks.
- Live smooth pitch changes, logarithmic 80–2,000 Hz slider, larger exact numeric field for 20–12,000 Hz, and optional 12-tone-equal note snapping (A4 = 440 Hz). When snap is off, exact Hz is preserved. Quick C4, A4 and C5 presets show English and Mongolian fixed-do names.
- Volume, reset, Mongolian by default (use `?lang=en` for English), and collapsed Settings containing the current tuning label and a time-window toggle.
- Two labeled **ideal mathematical** plots: a time-domain waveform and a relative-amplitude harmonic spectrum. The time plot defaults to the **same 20 ms window**, so higher frequencies visibly fit more oscillations; its caption gives the number of cycles. Uncheck the fixed-window setting to zoom to four periods for inspecting the wave shape. The plotted amplitudes, harmonic numbers and waveform shapes come from [sound-model.js](sound-model.js). These are **not** a microphone FFT or a live measurement of the speaker output.
- Small experiments and explanations about period, pitch, and harmonic content.

## Added in P2A: Strike & Pluck

- A second **Strike/Pluck / Цохих/татах** mode with **generated models**, not recorded instruments: initially an additive plucked string and a downward-sweeping bass drum, plus a modeled piano strike (added in P2D). Guitar and drum gained more physical models in P2G, and piano in P2H.
- Tap-to-trigger interaction, adjustable impact strength and decay time, plus a logarithmic pitch control for the string. The drum has no misleading single-note selector.
- One shared browser AudioContext across Pure Tones and Strike & Pluck. Each strike is a short one-shot buffer. A triggered voice has a 0.21 linear gain cap; at most four voices can overlap, for a worst-case sum below full-scale. The global Stop, category changes and page hiding silence them. No autoplay, microphone or outside network calls.
- Independent [transient model tests](sound-transient.test.cjs) and extended [UI/audio simulation tests](sound-ui.test.cjs).

## P2A plot and controls refinement

- The transient mode now has **one navigable waveform plot**, replacing separate envelope and 20-ms charts. It opens with a fixed 0–3 s view; use +/- zoom, left/right pan, Fit, or 1 s / 200 ms / 20 ms presets. At full duration the min/max traces show the decay envelope without aliasing; zoom in to see the individual oscillations. The vertical cursor and blue-shaded analysis window remain visible when their time range intersects the plot.
- The **local Fourier spectrum** below uses a Hann-windowed 2048-point FFT (16 kHz model sampling; **128 ms analysis window**) of the same mathematical waveform as the speaker signal. Its analysis window is independent of waveform zoom. The fixed -60 to 0 dB relative scale lets fading harmonics visibly decrease rather than rescaling each frame to full height. Toggle to the time-averaged **Whole sound** spectrum for comparison.
- **Synchronization:** when the user taps Pluck/Strike, the time cursor and local spectrum follow the latest hit according to the Web Audio context clock. Another tap starts following the newest hit, even when earlier bounded voices still decay. On completion or Stop, the display remains available. Dragging the time slider or clicking the waveform switches to passive manual inspection without replaying or altering the actual audio. It never autoplays.
- The string pitch control now has an independent **Snap to notes** switch using the same 12-TET note resolution as Pure Tones. With Snap off, the exact entered frequency remains unchanged.
- The drum has **Large / Medium / Small** presets and, since P2G, a membrane-tension slider. It deliberately does not display a spurious musical-note selector. Changing a recipe control stops the previous triggered buffer so the plotted model cannot silently disagree with an earlier hit.
- [sound-spectrum.js](sound-spectrum.js) is a dependency-free analysis module. It and the updated [sound-transient.js](sound-transient.js) are testable without a browser. All graphics are modeled output or FFT of that model, not microphone measurements or the sound actually emitted by speakers.

## Added in P2B: Moving Pitch

- **Moving Pitch / Хувирдаг давтамж** illustrates changing frequency in two ways, without asking for microphone access or loading external sounds. It is the fourth of five top-level categories after the added held-sound category.
- **Theremin:** drag or hold a pointer on the rectangular pad. Horizontal position changes frequency **logarithmically from 120 to 1,600 Hz**; vertical position changes volume (top is louder). Releasing or cancelling the pointer stops the sound. Keyboard users can focus the pad, use the arrow keys to change the sound, Space/Enter to start or stop it, and Escape to stop.
- **Siren:** compare three frequency trajectories using the same low/high limits, repetitions per second (0.2–2), and volume: **Огцом / Abrupt** (a sharp two-tone alternation), **Аажим / Smooth** (sinusoidal frequency change: slow near either extreme, fastest midway), and **Шугаман / Linear** (geometric Hz interpolation: equal musical-pitch intervals per second). We removed the former linear-in-Hz option to keep the audible comparisons focused. Switching trajectories while playing updates the same oscillator without restarting it. The Siren Play/Stop button is always a deliberate user action; nothing starts on page load or when a trajectory changes.
- The **frequency-versus-time graph** has a logarithmic vertical scale. The linear-in-pitch path produces straight rising/falling lines, while the smooth path has rounded turning points; abrupt means instantaneous ideal jumps. All three are evaluations of one tested deterministic model shared by the graph and target audio frequency. Web Audio applies a short (~18 ms) smoothing time to live parameter updates, so physical playback approximates the ideal, especially at abrupt jumps.
- A **pitch-versus-time** graph shows the siren's mathematical four-second pattern or the theremin's actual browser-interaction history. Once playback exceeds four seconds, the graph advances as a rolling window. The lower plots show the **20 ms ideal waveform** and **harmonic composition** at the instantaneous fundamental pitch; these are not sound-card or microphone measurements. The siren uses a pure sine oscillator; theremin timbres use normalized Web Audio periodic waves. Frequency and gain are smoothed as controls move.
- Display units follow the interface language in all modes, including controls, hints and chart axes: Mongolian uses **Гц**, **кГц**, **сек** and **мсек**; English uses **Hz**, **kHz**, **s** and **ms**. Changing language never alters the stored numerical frequency or time.
- Shares the existing browser AudioContext and master Stop. Audio has a 0.24 maximum linear amplitude, starts and ends with short gain ramps, is silent on mode changes or page hiding, and uses generation tokens to cancel pending starts safely. There is no autoplay, upload or network transmission.
- A separate dependency-free [motion model](sound-motion.js) and [motion model tests](sound-motion.test.cjs), plus simulated pointer, keyboard, siren and sound-lifecycle coverage in [UI tests](sound-ui.test.cjs).

## Added in P2C: Combine Waves (audible beats)

- **Combine Waves / Долгион холих**, now the fifth category, demonstrates interference using **two real, simultaneous sine oscillators** on the shared audio bus. Initial frequencies are **440 + 444 Hz**, yielding four loudness pulses per second. Audio starts only on an explicit Play press; changing modes, hiding the page or pressing the red Stop safely ends both voices.
- Change the first frequency between **120–1,000 Hz** using a slider or exact numeric entry, and set the **difference Δf from 0–20 Hz** using a slider or four child-friendly shortcuts (0, 2, 4, 10 Hz). The two frequencies, pulse rate and ideal plots update live without accumulating oscillators. Regular retuning reuses the same pair; returning the gap to zero smoothly replaces the pair with phase-aligned voices so the sound does not accidentally disappear through frozen phase cancellation. At Δf = 0 both tones are identical, so there is no pulsing. A separate volume slider controls both oscillators together, with a **0.24 steady-state combined peak amplitude cap** at full volume and smooth gain ramps (each sine is capped at 0.12).
- The upper **time plot** defaults to a one-second window and shows the exact mathematical **beat envelope** ±|cos(πΔft)|. At coarse scales it suppresses the carrier oscillations that would otherwise be aliased into a deceptive low-frequency curve. Use **− / + zoom** in fourfold steps between **4 s and 2 ms**, with a live visible-time label, and **← / →** to move the window across the first four seconds. When individual carrier cycles can fit without aliasing, the **actual summed waveform** appears in blue alongside the green envelope, and the caption explains the two traces. The time axis is localized to seconds/milliseconds.
- The lower **ideal spectrum** magnifies the narrow frequency interval so both peaks are individually visible. It shows exactly two source frequencies of half amplitude, or one merged peak at Δf = 0; **there is no third spectral peak at Δf**. The caption explicitly switches to explain the single peak when the two input frequencies match. This ideal line spectrum is not a live FFT or a microphone measurement. The new [deterministic beats model](sound-beats.js) and its [unit tests](sound-beats.test.cjs) share the same formulas as the educational plots.
- REC works across mode changes and captures both voices, with WAV preview and local download. The preview fallback is now labeled **Download WAV / WAV татах**, avoiding the confusing “again”; the global Stop still ends and saves an active recording.

## Added in P2D: harmonic builder, noise explorer and piano strike

- **Combine Waves / Долгион холих** has three small experiments: the existing **Two-tone beats**, **Build harmonics**, and **Explore noise**. Changing experiments stops the previous sound without automatically starting the next one. Each experiment has its own small challenge and explanation; no extra navigation tier or unfinished feature placeholder is shown.
- **Harmonic builder:** Start from a 120–1,000 Hz fundamental, use **Pure**, **Odd** and **Rich** mixtures, or set the strengths of eight harmonics individually (f through 8f). The fundamental is always present (at least 10%); upper partials can be muted. The blue 20 ms waveform is the mathematically normalized sum of the same sine coefficients used to create a Web Audio `PeriodicWave`, and the eight spectral bars show their selected strengths. While playing, the pitch and volume adjust live; changing the harmonic mixture crossfades to a new oscillator to avoid clicks. The voice has a 0.24 gain cap at 100% slider volume. [sound-harmonics.js](sound-harmonics.js) keeps the additive recipe independent of the UI so it can become an instrument in Compose.
- **Noise explorer:** Listen to locally synthesized **white**, approximately **pink** (octave-layered) and **brown** (leaky-integrated) noise. A user-adjustable second-order low-pass filter changes brightness; its cutoff is 250–8,000 Hz. Playback uses a reproducible two-second Web Audio buffer loop through a `BiquadFilterNode` and a bounded gain with a gentle fade; color changes crossfade to a new loop. At full slider volume the noise gain is capped at 0.20; the default is only 25%, with a headphone safety reminder. The 40 ms waveform shows an illustrative, approximately filtered noise segment. The lower **predicted frequency distribution** conveys the broad colored-noise and low-pass trend; it is deliberately **not** a real-time FFT, spectrum of the recorded audio, or measurement of the speaker. The independent [sound-noise.js](sound-noise.js) supplies deterministic samples and an educational expected spectrum.
- **Modeled piano (initial P2D preset):** A third choice in **Strike/Pluck**, next to string and drum, with the same one-tap button, pitch/optional note snap, strength, decay, waveform zoom and Fourier spectrum. No keyboard or note-editor UI. The original preset had eight inharmonic partials, three near-unison strings and a short hammer onset; P2H later replaced this with a more detailed modal model, and P2I added a short-tap damper preset. Future Compose can supply arbitrary note-off timing.
- All three new sounds pass through the existing shared Web Audio output and the header's local WAV recorder. Language remains **Mongolian by default**, with English switching and localized Гц/мсек/сек labels. Changing top-level modes, experiment, hiding the page or pressing master Stop stops active or pending starts safely. There is no microphone use, network request or autoplay.
- Model and simulated browser tests now cover [harmonics](sound-harmonics.test.cjs), [noise](sound-noise.test.cjs), [piano transients](sound-transient.test.cjs), and the expanded [interaction and audio lifecycle](sound-ui.test.cjs).

## P2E: Timbre and interface consistency

- In **Moving Pitch → Theremin**, four selectable synthesis colors—**Цэвэр / Pure**, **Баян / Rich**, **Хоолой шиг / Voice-like**, and **Дээд авиа / Overtones**—combine different strengths of f through 8f. The pad still controls pitch and volume, and the Siren remains a pure sine. Changing color while playing crossfades bounded oscillators. The lower waveform and harmonic bars use the same [sound-motion.js](sound-motion.js) coefficients as the audio. These are deliberately stylized periodic timbres, **not** recordings of a voice or traditional throat singing; the emphasized harmonics move with the fundamental.
- In **Combine Waves**, the experiment choices now appear in **each left control panel**, matching other modes instead of forming an extra tab bar across the page. Their short Mongolian names are **Хоёр давтамж / Өнгө бүтээх / Шуугиан** (English **Two frequencies / Build timbre / Noise**). All three large buttons read **Тоглуулах / Play** when idle and **Зогсоох / Stop** when active. Each experiment preserves its own controls and remains silent when selected.
- The piano strike uses a more distinctive hammer-onset mixture and slight multiple-string beating. In future Compose, both plucked and hammered notes should share pitched-string parameters while retaining separate presets for excitation and note-off behavior.

## P2F: Held instruments — Blow & Bow

- A fifth top-level category, **Үлээх/нумдах / Blow/Bow**, sits directly after Strike/Pluck. Its three original **generated** sound presets are **Лимбэ / Flute**, **Хийл / Violin**, and **Морин хуур / Morin khuur**. They are deliberately simple harmonic models with soft filtered breath/bow noise. The violin emphasizes higher harmonics, the flute is nearly sinusoidal, and the morin-khuur-inspired preset emphasizes a different set of partials. These do **not** reproduce real acoustic instruments, soundboards, articulation, bow friction or Mongolian throat singing.
- **Hold** (default): press and keep the large button down with a touch pointer or mouse; release/cancel to fade out. With keyboard focus, holding Space/Enter sounds the note and key-up releases it; Escape stops. The browser also supports an accessible synthetic-click fallback. **Tap to toggle** is an explicit alternative for phones, accessibility devices and longer listening: one tap starts, the next releases. No note starts when choosing a preset, moving sliders or switching tabs. Global Stop, page hiding and window blur stop the note and cancel pending async starts.
- Common exact frequency 110–880 Hz with optional independent 12-TET Snap, volume, **attack** 0.02–0.6 s and **release** 0.04–1.2 s. The note remains at its selected level as long as the user holds/toggles it; release fades according to the chosen time. Changing pitch/volume during a held note works live; changing attack affects the **next** note, while changing release affects the next release. There is no arbitrary fixed note duration, though plots use a labeled **1.2 s illustrative hold**.
- **Graphs:** a 2.6-second fixed-axis amplitude-envelope example has attack, steady sustain and a marked release at 1.2 s; changing attack/release updates its curve. Below are an ideal 20 ms harmonic waveform and an eight-bar harmonic composition using the *same periodic-wave coefficients as playback*. The filtered breath/bow noise is deliberately omitted from the ideal periodic plots, which are not real-time audio measurements.
- Synthesizer implementation in [sound-sustain.js](sound-sustain.js) and [sound-lab.js](sound-lab.js): eight-harmonic Web Audio `PeriodicWave`, low-gain looped seeded noise through a lowpass filter, one shared bounded amplitude envelope, and a maximum full-volume gain of 0.22 (before mild noise texture). Sources are bounded and disconnected after release, compatible with the global WAV recorder. Pure-model and simulated browser [tests](sound-sustain.test.cjs) cover envelope continuity, timbre differences, pointer/keyboard/toggle gestures, early-release cancellation and cleanup.

## P2G: modeled guitar, chord strumming and membrane drum

- **Guitar:** [sound-string.js](sound-string.js) uses a compact Karplus–Strong-style delayed-feedback string with a two-tap low-pass loop loss, fractional delay for tuning, triangular initial displacement set by pluck position (8–50% of the string), and a tiny initial pick click. An internal bounded cache supports random-access samples for short-time Fourier analysis without re-running the feedback loop for each plotted point. It is generated audio, not a recorded guitar; the guitar body and fret/bridge resonances are not yet included.
- **Several strings together:** Within the same guitar controls, choose **One string / Нэг чавхдас** or **Several strings / Олон чавхдас**. The latter strums a standard E2–A2–D3–G3–B3–E4 six-string guitar using three introductory chord patterns: **Em** `[0,2,2,0,0,0]`, **G** `[3,2,0,0,0,3]` and **C** `[-1,3,2,0,1,0]`, lowest string first; `-1` is muted. Each string is independently generated at its fretted pitch, started 12 ms after the previous physical string, and combined into a peak-bounded buffer. The pitch slider appears only for a single string; both styles have a pluck-position control. One button triggers a complete strum; no keyboard or fretted guitar picture is required. The chord-generation routine can be reused by Compose with arbitrary fret patterns later.
- **Membrane drum:** Eight modes of a circular membrane use ratios of Bessel-function zeros, not integer harmonics. The approximate fundamental is 112 Гц for a medium drum at 100% tension and scales inversely with radius and as the square root of tension. The UI offers three relative sizes and a 50–200% tension slider. Mode-specific decay constants and a short bright knock make a generated percussion sound; this is not a detailed bass-drum shell/cavity model. The former descending-pitch electronic kick has been replaced, not accidentally conflated with a physical membrane.
- **Held timbre correction:** Flute has a slightly purer spectrum, violin has a quicker onset, and the Морин хуур illustrative preset now permits a stronger second than first harmonic and starts/releases more briskly. These are provisional improvements, **not** a calibrated physical model of the Mongolian instrument; measured-body resonances, bow friction and breath pressure remain future work.
- The audio buffer, zoomable waveform and local/whole Fourier spectrum use the **same recipe and sample generation**, including all chord strings and each membrane mode. Changing any control stops the previous hit; there is no autoplay. [String tests](sound-string.test.cjs), [transient tests](sound-transient.test.cjs), [spectrum tests](sound-spectrum.test.cjs) and [interaction tests](sound-ui.test.cjs) cover tunings, chord presets, mode ratios and buffer/plot consistency.

## P2H: velocity-sensitive piano and concise instrument labels

- **Piano:** [sound-piano.js](sound-piano.js) replaces the original additive preset with an 11-mode, slightly inharmonic stiff-string model. Three close-tuned strings per note beat against each other. A hammer excitation spectrum approximately models felt hardness and a strike point around one seventh of the string; higher notes of that spectrum are stronger on harder strikes. Each mode has **fast initial and slower late decay** (with faster damping of upper modes). Broad frequency-dependent resonances color the output like a simplified soundboard response; a tiny brief contact transient adds attack. This is a teaching approximation, **not a numerical hammer collision or coupled string–bridge–soundboard simulation**.
- The existing **Цохилтын хүч / Strength** slider for piano now changes **both loudness and spectral brightness**. The same waveform samples feed speaker playback and the local/whole FFT, with a bounded cached 48 kHz synthesized reference wave to avoid redoing multiple sine evaluations during every pan, zoom and spectrum request. At P2H there was no keyboard, key-release control or audio file. P2I subsequently added a fixed short-tap damping option; arbitrary note-off and sympathetic resonance remain future additions.
- The main tabs now read **Цохих/татах** and **Үлээх/нумдах** in Mongolian, **Strike/Pluck** and **Blow/Bow** in English. In guitar's **Олон чавхдас** mode, the performance button is **Цохих** (strum); **Татах** is reserved for a single pluck.
- Further model ideas: B. Bank's [piano synthesis thesis](https://home.mit.bme.hu/~bank/thesis/pianomod.pdf) motivates coupled detuned modes and two-stage damping; Giordano and Jiang, [*Physical modeling of the piano*](https://docs.lib.purdue.edu/physics_articles/392/) discusses fuller hammer, string and soundboard coupling. These are conceptual references, **not** claims that this simplified model reproduces their simulations.

## P2I / S019: piano late tail and key-touch comparison

- The three modeled strings now have narrower, frequency-capped unison detuning and a more stable central component; upper modes lose more energy during the long decay. This preserves mild beating but avoids the former near-cancellation of the fundamental and disproportionately metallic late overtones (observed around 284.5 Гц at 1.5–2 seconds). It is an illustrative *coupling/decay adjustment*, not a measured piano calibration.
- The main piano performance button reads **Дарах / Press**. An adjacent **Тоглох арга / How to play** choice switches between **Дарах / Press** (a held-key free-decay illustration) and **Товших / Tap** (a gentler hammer strike with modeled key release after 0.16 s and a smoothly returning damper). The touch choice is independent of the existing strength and natural-decay sliders; no piano keyboard has been added.
- Playback buffers, the waveform and the local/whole Fourier analyses use the same selected touch and velocity. Switching touch does not autoplay and stops the previous modeled strike. Model regressions compare late fundamental/overtone balance across 110–880 Hz, tap/press envelopes, audio/plot sample agreement, bilingual UI labels and silent selection. A real key's arbitrary hold duration and a sustain pedal remain future Compose controls.

## Audio headroom and device limits

- Bounded gains across the five top-level modes: Pure Tones peak 0.30, modeled strikes 0.21 per voice (maximum four simultaneous), held notes 0.22 before mild texture, Moving Pitch 0.24, beat pairs 0.12 per oscillator (0.24 summed), harmonic builder 0.24 and noise explorer 0.20. The master output isn't a dynamic compressor; headphone/device gain still matters. Existing volume slider defaults remain unchanged; model waveforms and spectra still show mathematical signals rather than a calibrated loudness measurement.
- These are bounded **linear audio amplitudes**, not calibrated loudness or device output in decibels. Small phone speakers often cannot reproduce low bass even when the generated signal is louder, and raising gain does not restore frequencies they cannot physically produce. Start quietly when switching to headphones or larger speakers; there is no automatic loudness normalization or bass enhancement.

## Local WAV recording

- One small **● REC** button lives in the sticky title bar beside the language switcher and global Stop. Press it, then play pure tones, strike modeled instruments (including piano), hold or toggle a flute/bowed sound, move the theremin, play a siren, compare beats, construct a harmonic mixture or explore noise. While recording, the same button switches to a **⬇ WAV** (Stop/Save) action with an elapsed-seconds counter. There is no permanently open recording panel occupying space below the mode tabs. Switching modes or mini-experiments during a recording is supported; moments of silence are part of the file.
- Recordings are mono **16-bit PCM WAV**, capped at **15 seconds**. Pressing Stop/Save or the master Stop finalizes the capture and **initiates a local WAV download**. Reaching the cap also initiates a download. A small dismissible preview appears under the title-bar button, containing a built-in audio player and a clearly labeled **Download WAV / WAV татах** fallback link if the browser blocks the automatic download (also usable to save another copy). Timestamped `.wav` filenames identify captures. The browser keeps bytes locally (object URL); it never requests microphone access or transmits audio to a server. Hiding or leaving the page ends recording without an unsolicited automatic download.
- All modeled voices route to one shared gain bus that goes to the speakers and, while recording, to an [AudioWorklet capture processor](sound-recorder-worklet.js). The capture processor sends bounded Float32 sample chunks to the [recorder and WAV encoder](sound-recorder.js) and emits **silence** on its connected output so playback is not doubled. Worklet timing, the 15-second cap, PCM headers and playback/control lifecycle have automated tests in [sound-recorder.test.cjs](sound-recorder.test.cjs) and [sound-ui.test.cjs](sound-ui.test.cjs).
- This records **generated app audio**, not the microphone, external music, or ambient sounds. A browser without AudioWorklet support can still use the sound modes; the header recorder reports an error when recording is unavailable. On narrow phones, the control becomes an icon-only button with an accessible label.

## Future extension boundaries

Keep three concepts separate:

1. Pitch identity: symbolic note or explicitly entered Hz.
2. Tuning context: P1 resolves symbolic notes through 12-TET only; later just/Pythagorean/alternative scales change how notes resolve into frequencies, not the written score.
3. Sound recipe: waveform/timbre, modeled drums, piano and plucked strings, **held flute and bowed strings**, eight-partial harmonic mixtures, three noise colors, moving pitch and two-oscillator interference now; later richer articulation, modulation and score-driven instruments.

**Next candidates, not yet shipped:** a stylized **cymbal** (rapidly decaying plate modes and filtered noise), **steel pan** (tuned plate modes) and snare/other modeled drums belong with Strike/Pluck. Piano still needs a physically modeled nonlinear hammer collision, measured soundboard coupling and a damper controlled by note-off. Richer held-sound features might include bow pressure, vibrato, instrument resonances, changing breathiness and a **voice/formant or throat-singing-like model**. The first held sounds now supply note-on and note-off with adjustable envelopes; future Compose should schedule those same recipes by note duration, not duplicate the synthesis engine. Acoustic fidelity and touch behavior still need direct device listening tests.

Later work will add Compose and Analyze **when usable**, rather than displaying disabled tabs now. Score-wide tunings belong in Compose; Explore tunings stay in Settings and only affect note snapping. A score can reuse piano, plucked string, percussion, harmonic mixtures and later held sounds with independent note-on/note-off controls; it will not need its own piano keyboard graphics.

Manual browser checklist (not covered by Node model tests):

1. Open the page in Chrome/Firefox/Safari on desktop and phone; no sound before Play.
2. Start Play, change wave, pitch and volume while sounding, then Stop. Test rapid changes and visibility loss. Check headphone volume carefully.
3. Check raw 437 Hz stays 437 with Snap off; turn Snap on and verify it rounds to A4 = 440 Hz.
4. Compare sine (one modeled peak), triangle and square (odd peaks), and sawtooth (all peaks). Raise pitch and watch cycles pack into the fixed 20 ms window, then uncheck the fixed-window setting to see four large periods.
5. Confirm the bare URL opens in Mongolian and `?lang=en` opens in English; tab through controls with the keyboard, including Play and Stop; resize the page and ensure the charts remain readable.
6. Enter Strike & Pluck. Confirm switching modes is silent until a tap. Try one guitar string at 220 and 440 Hz with Snap off/on; move pluck position toward the end and listen for extra brightness. Switch to Several strings and tap **Em**, **G**, and **C**; listen for the short sweep of individually pitched strings and compare the spectra. Then try all three drum sizes and vary membrane tension. Verify the drum has size/tension controls instead of a fake note selector; tightening raises its stable modal frequencies.
7. Compare 0–3 s, 1 s, 200 ms and 20 ms waveform views. Zoom and pan across the decay, then Fit; use both the time slider and clicking the plot to inspect different moments. Confirm the local spectrum evolves and the Whole sound toggle stays constant.
8. Tap several times: the time cursor should follow the **latest** hit, reaching its end without unintended replay. On Stop, the cursor stops and manual scrubbing still works. Change strike strength/decay, switch back to Pure Tones, and check that no hidden voice or loop continues. Test on phone speakers and headphones at low volume.
9. Enter Moving Pitch. Without a click, confirm silence. Select each of the four Theremin **timbres** while silent, then hold or use the keyboard to sound the pad and switch color: check that the waveform and harmonic bars change in agreement with the audio, without extra lingering voices. Move around all four corners: right is higher frequency and top is louder. Release outside the pad; the sound should stop. Tab to the pad, use arrows, Space/Enter and Escape; check the focus indicator and `aria-pressed` state.
10. Switch to Siren. Play all three trajectories: **Огцом** (abrupt two-tone), **Аажим** (smooth sinusoidal), and **Шугаман** (linear in semitones). Keep the same limits and repetition rate while switching and compare their sound and graph curvature. Vary limits/speed while playing; verify the four-second graph, readout and instantaneous wave/component respond. Check that Stop, language changes, Reset, mode switching, browser tab hiding and the global Stop do not leave hidden audio playing. Confirm the rolling graph is continuous past four seconds.
11. Enter Combine Waves: verify silence until Play and default 440 + 444 Гц → 4 pulses/s. Try the four gap shortcuts and drag the gap from 0 through 20 Гц while playing. At zero, the loudness should be steady; for gaps 2 and 4, count the slow pulses; at 10 and 20, notice faster pulsing/roughness. ## Scientific/technical limits

- Ideal Fourier magnitudes are relative to the fundamental; actual speaker/headphone responses, Nyquist filtering and hearing vary. The waveform plot is a mathematical model and the spectrum omits harmonic phase.
- There is no maximum listening-time or dB calibration; users should start at low volume, particularly with headphones.
- Higher frequencies may be outside the effective bandwidth of a device; avoid presenting them as proof of a child's individual hearing range.
- The local FFT analyzes a mathematically generated signal, not live microphone or sound-card audio. A short-time spectrum necessarily trades time resolution for frequency resolution; this release fixes its window at 128 ms, especially relevant for very low drum frequencies.
- This release has WAV export of locally generated sounds and three preset guitar chord strums; it has no microphone analysis, recording of external sounds, tuning comparison, editable score or general melody playback.
- Guitar uses a compact delayed-feedback ideal string with an illustrative pick transient; piano uses modal, inharmonic, velocity-dependent damped partials and near-detuned unisons with a **broad static soundboard coloration**, not full measured/coupled resonances. Both omit much of a real instrument's body response. Piano **Товших** only approximates a damper returning at a fixed short interval; the model has no continuously controlled key-release event, sustain pedal, nonlinear hammer–string collision or sympathetic resonance. The drum uses a limited sum of circular-membrane modes; it does not solve membrane dynamics with shell, air-cavity coupling or nonlinear head tension, and the current strike point is fixed.
- Flute, violin and morin-khuur-inspired models use eight periodic harmonics plus a little synthetic low-pass noise. They omit instrument-body resonances, nonlinear bow/friction physics, breath dynamics, resonator coupling and characteristic articulations; comparing their harmonic bars teaches sound-color differences, not instrument identification. Attack and release are explicitly modeled gain curves. The envelope graph assumes an *illustrative* fixed 1.2-second hold, while the audible note sustains until the user releases or taps Stop; acoustic device testing is still required.
- Theremin timbres are **modeled moving-frequency harmonic oscillators**, not actual theremin, human-voice or throat-singing recordings. The siren uses a pure sine; its graphical path is a mathematical prediction. The theremin's harmonic bars show an **instantaneous ideal periodic spectrum**: a real, rapidly frequency-changing oscillator creates additional time-dependent spectral spread, while a real voice has more complicated formants that do not simply track the fundamental pitch.
- The beat plot is the mathematical sum of equal-amplitude, steady sine waves. Retuning live in Web Audio briefly glides frequency; transient audio, room acoustics, and the listening device may add artifacts that the ideal two-line spectrum cannot show. At the upper end of the Δf slider, a child may hear roughness rather than distinct individual pulses.
- The harmonic builder uses eight sine partials with common phase and Web Audio's periodic-wave normalization. An instrument's timbre also depends on phase, transient envelope, noise and inharmonicity, which these eight sliders do not model. At high fundamentals some upper partials may be above the effective bandwidth of the speaker.
- Pink/brown noise colors are illustrative stochastic models, not standardized noise sources or calibrated spectral-density measurements. The generated buffer is finite and looped; the plotted response is an analytical power-law approximation (including idealized low-pass attenuation), not a measured FFT of the actual generated or filtered buffer. The displayed noise waveform uses a two-pole smoothing approximation for explanatory purposes; the browser playback uses a Web Audio biquad. Colors may sound very different on phone speakers or low-frequency-limited devices.
